## 一、P0：行为分叉风险（重复的代价已经显形）

### 1.1 `confirmActivityMissionList` 漏做 coin 同步 —— 单条/列表版复制后单向演化

### 1.2 building 生产结算 11 处直写库存，绕过 `items:get` 事件通道
- `app/game/manager/building.ts` L1339/L1890-1906/L1902/L2199/L2225/L2235/L2245/L2461/L2474/L2530/L2631 直写 `draft.inventory[...]`/`draft.status.gold`，绕过 `InventoryManager.gainItem` 的类型分发，**也不触发** TotalSimpleTokenCount/ActivityCoinGain 等勋章任务事件（inventory.ts L53-60）。

## 三、模板级同构（量大、机械、收益高）

1. **游戏路由样板**（最大量）：40 个路由文件约 750 条路由；`res.send(player.delta satisfies X)` 结尾 **201 处**；`req.body as X;` 无用空断言 **624 处**；60%+ 为「校验→转发→回 delta」纯转发或 stub 同构。
   建议：`handle(schema, fn)` 包装器 + `sendDelta(res, player, extra?)` + stub 表驱动注册。**约束：player.delta 一次请求只能读一次**（getter 清 _changes 并触发保存），helper 必须保证单次读取。
2. **admin-router try/catch**：`res.status(400).json({error:(err as Error).message})` 逐字出现 **71 次**（crisis.ts 另有 5 处）。建议 `wrap(handler)` 高阶函数或统一错误中间件。
3. **medal.ts 勋章模板**：~110 个方法重复同一 `funcs{init,update}` + `funcs[mode](args)` 样板（全文件 3323 行）。建议表驱动：一张 `{init, update}` 注册表 + 单一 runner。
4. **SSE 回填+订阅样板 ×5**：admin-router.ts:1093/1177/1189/1201/1251 五处同构；且 `/api/logs/stream` 的 kind=capture 分支与 `/api/capture/stream` 直播同一数据、无 UI 消费者（Dashboard 日志 Tab 只有 server/audit/watchdog）。建议抽 `sseStreamWithBackfill()` 并删除 kind=capture 分支（同步修正 log-service.ts:60 LiveLogKind）。
5. **config 路由文件内复制**：prod.ts:34-74 三个平台版本端点重复同一 12 行签名块 ×3；remote-config buildNetworkConfig ×4；gate meta/info 仅差一字段；auth.ts 路径别名整段重复注册。建议平台参数化循环注册 + 共享 body 函数。
