主干 DI 早已完成（构造注入 + 组合根工厂 + 端口），**继续"全量 DI 化"收益递减**；
本次按"缺口驱动"只补两处真缺口，并把成果用棘轮守卫固化：

| 项 | 结论 | 本次动作 |
|---|---|---|
| 构造注入 / 组合根 | 已完成，无需再动 | — |
| excel 数据单例（140 文件 / 198 处 import） | **可行且必要** | 落地 `kernel/excel-port.ts` + `player.excel` + 数据目录解析 + 棘轮守卫，增量迁移 |

## 4. 明确不做（附理由）

- **DI 容器 / 装饰器自动注入**：`tsconfig.json` 无 `experimentalDecorators`/`emitDecoratorMetadata`，
  运行时是 **tsx 4.23（esbuild）** 与 **vitest 4.1（esbuild）**，esbuild **不支持 `emitDecoratorMetadata`**——
  只有切到 tsc 构建才能生效，同一份代码在 dev 与 test 会行为分叉。且本项目生命周期根唯一
  （`PlayerDataManager`，每 uid 一个），容器要解决的作用域问题不存在；解析顺序不可控反而弱化
  `composition-order.test.ts` 的行为不变量。
- **`PlayerDataManager` 门面接口化**：router/模块层 83 处 `_trigger.emit` + 122 处 `_playerdata` 是既有合法用法，
  接口化会打破它们；而"可替换"这一收益已被 `mockPlayerData` 提供。
