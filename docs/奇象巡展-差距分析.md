## 0. 摘要

奇象巡展是本服首个 **ARK_HUB 型**活动（`act1arkhub`，2026-08-08 16:00 ~ 09-04，rewardEnd 09-06）。当前实现已打通**进入大厅、场景渲染、切场景、引导、活动任务领取、兑换商店、ARKDUEL 假战斗**全链路（官服抓包字节级对齐），但玩法主体仍为"假响应"：

- **勋章**：3 枚勋章数据在表，模板全部未实现 → 永远无法解锁；
- **生物数据源**：珍奇度/属性/六维/特质/变种 **无任何数据来源**（excel、enemy_database、arkvent 均无）→ 寻迹、拟合、勋章、6 条收集任务全部依赖它，是最大前置缺口；
- **任务进度**：23 条任务播种即满进度、全部可领，无真实进度计算，8/18 后任务无日期门控；
- **ARKDUEL**：战斗为固定假响应（敌方 19005×5、固定奖励 act1arkhub_14），无胜负结算、无 15/7 券发放、无对决规则；
- **ARKDEX 寻迹 / 道具 / 交换 / 像素画持久化**：均未实现。

以下按 P0~P3 分级给出缺口清单与分阶段实施计划。

## 3. 缺口清单（分级）

### P0 — 核心链路断裂（无这些，活动"看似能玩实则没内容"）

**P0-1 勋章模板未实现（medal.ts）**
- 现状：`medal_activity_1arkhub_01/02/025` 定义在表；`MedalProgress` 按模板注册监听，`(template in this)` 不成立即 throw `template not implemented yet`。三者均未实现 → 勋章界面进度恒 0、永不解锁、syncInfo 推送的 medals 无效。
- 要求：`ActivityArkhubPixelCollect`（unlockParam [act1arkhub,0,4] → 收集画像 4 幅）、`ActivityArkhubCreatureCollect`（[act1arkhub,arkhubMissionCollection1,10] → 收录 10 种）、`ActivityArkhubAlterCollect`（[act1arkhub,arkhubMissionCollection1,10,1] → 10 种+1 亚种，origin=_02 镀层联动）。
- 前置依赖：画像收集计数（ARKPIXEL）、生物收录计数+亚种计数（ARKDEX）——即 P1-1 数据源。

**P0-2 生物数据源缺失（最大前置缺口）**
- 现状：珍奇度（1-3★+闪框）、属性（奇术/本能/百变）、六维（进攻性能=20 攻击 / 进攻速率=攻击间隔倒数×10 / 守备性能=2 防御 / 耐久性能=100 HP / 法术抗性=0.5 / 移动速度≈1.1 基准）、特质（能力+变种）、亚种、"活动频繁"标记——**excel/enemy_database/arkvent/item 均无**。
- 影响面：寻迹（P1-3）、拟合配置与克制（P1-4）、勋章 02/025（P0-1）、任务 9~14（收集 N 种）。所有玩法都消费这份数据。
- 来源候选：① 官服网关抓包（EnterSceneNotify 之外应有生物/道具实体帧）② 客户端资源逆向（`tmp/` 或 `reference/` 中已下载的 AssetBundle/代码）③ 手工建本地表（最慢但确定）。

**P0-3 任务进度全假**
- 现状：播种 `state:2, progress=[{1,1}]` → 23 条全可领；`syncInfo` 又把未完成的任务强制 progress=[{1,1}]。客户端永远"全完成"，与攻略逐条对应关系失真；8/18 后任务（7/8/12-14，param 日期区间 `2026-08-18 16:00:00` 起）无日期门控。
- 要求：按 8 类模板做真实进度（见下表），8/18 任务在 08-18 16:00 前不可见/不可领。

| 模板 | 任务 | 进度来源建议 |
|---|---|---|
| `ArkhubMissionCompleted` | 1-3 引导 | 网关 GuideFlags（capture_catch_guide_01/02、arkdex_battle_guide）→ 已实现，可映射 |
| `ArkhubDailyMissionCompleted` | 4-8 每日物资（param: 活动区间+8/18 区间+天数） | 服务端记录每日物资领取天数 |
| `ArkhubCreatureCollection` | 9-14 收集 N 种（param: N+collection key，12-14 为"活动频繁"） | ARKDEX 数据库收录计数 |
| `ArkhubCreatureCaptured` | 15 信息素扫描 1 次 | ARKDEX 捕获事件 |
| `ArkhubCreatureExchange` | 16 发起交换 1 次 | 交换站事件 |
| `ArkhubPassDexBattle` | 17-19 拟合 N 次 | ARKDUEL 结算事件 |
| `ArkhubPublishPixelArt` | 20-21 发布 N 幅 | 像素发布事件 |
| `ArkhubCollectPixelArt` | 22-23 收集 N 幅 | 像素收集事件 |

**P0-4 ARKDUEL 无真实结算与奖励**
- 现状：战斗开始固定回敌方 19005×5+`act1arkhub_14`，结算回 code100；无胜负判定、无 15/7 券、无概率道具、无对决规则（快速 2 人 2 只 1 轮 / 常规 2 人 1 只 3 局 2 胜不可重复出战 / 多人 4 人 2 只 1 轮）、无属性克制 130%/70% 与六维参与。
- 注：战斗实际由**客户端本地演算**（服务器只下发敌队并收结算），故服务端重点是：① 结算帧解析胜负字段 ② 按胜负发 15/7 券+概率道具 ③ 计数（任务 17-19）。结算帧 0xb7c204e8/0xb7c2b07e 的胜负字段需抓包确认。

### P1 — 玩法主体缺失

**P1-1 ARKDEX 寻迹全流程**：遭遇（栖息地走动→4 干员编入→扫描→15 券+个体/失败无）、数据库收录（首收/变种）、扫描仪（400 内存、喜爱置顶、投影跟随）、保护区（守门人拟合胜利解锁、珍奇度 3）。
- 服务端角色：持久化 `ARK_HUB` 下的生物数据库/扫描仪/捕获记录；发券；驱动任务与勋章进度。遭遇本身大概率客户端本地+网关帧，需抓包确认帧协议。

**P1-2 巡展道具**：购买（ARKDUEL 商店价格表已回，**购买帧未实现**；共享库存每日刷新：标准/专业/稀有诱引剂+随机 2 味诱引剂+随机 2 信息素）、持有与生效次数（离开会场不清除）、信息素广播（区域内所有人可扫、每人 1 次、限时隐藏）。

**P1-3 数据集换（交换站）**：设置需求（1 条、只能指定种类）、查看请求、发送/确认、来源游客显示、范围设置（所有人/仅好友）。

**P1-4 奇象拟合数据配置**：3 只、稀有度之和≤7★、最多 3 组；属性克制 130%/70% 与六维数值至少需服务端下发正确敌队数据（是否本地模拟由客户端决定，服务端需提供数据）。

### P2 — 体验/持久化（私服可降级）

**P2-1 像素画服务端持久化**：`getPixelArt` 空、`savePixelArt` 空增量 → 客户端本地缓存可走完流程，但无跨端、发布/收集计数（任务 20-23、勋章 01）无来源。可选：本地文件存储（仿 OSS）+ 发布/收集计数上报。
**P2-2 多人/社交**：30 人广场、全服匹配、4 人同台、分会场（邀请码/好友邀请/5 分钟冷却）。私服单机无真实玩家，保留假响应即可；多人对决可本地 AI 模拟。`getFriendUidList` 空、匹配假响应可接受。

### P3 — 细节

- 每日物资每日限次校验（P1-1 的领取动作已有，计数与限次待补）；
- 切换广场/设置项（允许好友邀请、自动显示画像等）为客户端本地设置，无服务端需求；
- 专题网页（图纸分享/摊位 4 人）为网页功能，私服不适用。

## 4. 实施计划

> 遵循项目约定：路由挂 `app/game/app.ts`、状态走 `player.update` 配方、事件扩展 `EventMap`、日志走 `@utils/logger`、抓包补协议用 `tmp/capture/` 统一存储、类型生成表不改手。

### Phase 1（P0：让勋章/任务/结算闭环）
1. **生物数据本地表** `data/arkhub/creatures.json`（逆向来源标注）：id/名称/珍奇度/属性/六维/能力/变种表/亚种/活动频繁标记/栖息地/保护区/信息素诱引 id。同步 `app/excel/excel.ts` 注册。
2. **ARKDEX 状态扩展**：`defaultArkhubState()` 增加 `creatures`（数据库：种类+变种收录）、`scanner`（个体列表+内存计数）、`pixelArts`（发布/收集计数）、`dailySupplyDays`、`trade`（交换需求）。注意与官服 playerdata 形状兼容（§26.1 表，官服快照无这些字段——私有扩展字段放 `ARK_HUB[act1arkhub]` 下，客户端读不到也不影响）。
3. **medal.ts 三模板**：监听新事件 `arkdex:collect`（收录计数/亚种计数）、`arkpixel:collect`（画像收集计数），按 unlockParam 判进。测试：`tests/unit/manager/medal.test.ts` +3。
4. **任务进度真实化**：MissionProgress/事件驱动 8 类模板；`syncInfo` 去掉强制 `[{1,1}]`；播种改为 `state:2, progress=[{value:0,target:N}]`（N 从模板 param 解析）；8/18 任务按 param 日期在 08-18 16:00 前 `state:0`。`unlockActivity.ts` 同步调整。
5. **ARKDUEL 结算**：抓包确认结算帧胜负字段 → 按胜负发 15/7 券（token_seal + coin 同步）+ 概率道具 + 任务计数。

### Phase 2（P1：ARKDEX 玩法）
1. **遭遇/扫描帧逆向**：新号跑官方全流程抓包（capture 模式），补捕获开始/结束/数据库/扫描仪帧协议。
2. **道具**：ARKDUEL 商店购买帧实现（扣 coin、库存每日刷新、发道具）；诱引剂/信息素使用帧 + 生效次数持久化；信息素广播简化（单机立即出现，多玩家留接口）。
3. **保护区**：守门人拟合胜利 → 解锁 flag → CAPTURE 区可遇珍奇度 3。
4. **交换站**：需求设置/请求/确认 路由（HTTP 或网关帧），来源游客显示（uid=1 场景留字段）。
5. **每日物资**：领取天数计数（供任务 4-8）。

### Phase 3（P2：像素画 + 可选社交）
1. `savePixelArt` 落盘 `data/arkhub/pixels/{uid}/{id}.bin`（1728B RGB），`getPixelArt` 按 id 返回；发布/收集计数事件。
2. 可选：分会场/邀请码（uid 隔离）、4 人 AI 对决。

### 验证
- 每阶段：`pnpm exec tsc --noEmit` + `pnpm exec vitest run`（现有 1710 全绿为基线）。
- 实机链路：新号注册 → 播种 → syncInfo（进度/勋章）→ 领任务（coin 同步）→ getGoodList/buyGood → 网关全流程。
